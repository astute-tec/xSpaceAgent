# 声纹录入与识别修复（2026-11-18）

## 目标

声纹功能按“固定 5 个名额，其余统一归其他人”实现，优先保证录入可靠、删除一致、原始录音不留存，再修复多人会话的分段识别。声纹数据只保存在 Hub 私有目录，不进入 Mywork。

## 已确认问题

### 设备端

1. 点击名额后，任务真正启动前没有同步占用状态，连续点击会创建多个录入任务。
2. 录入中任意点击都会取消，并提前把 UI 改成空闲；旧任务尚未退出时可以再次创建任务。
3. 普通录音停止后只等待 3 秒，Flash 写盘或上传收尾稍慢就会误报失败。
4. 未检查 `xTaskCreate` 返回值；失败时界面会停留在错误状态。
5. 声纹上传只调用一次 `esp_http_client_write`，部分写入也可能继续读取响应。
6. 删除先清本地 NVS、后请求服务端，网络失败会造成设备和服务器状态不一致。
7. 名字缓存只有 12 字节，中文姓名和自定义显示名容易截断。
8. 录入前没有最基本的静音、有效语音和削波检查。
9. 录音页波形使用 RMS 驱动的合成正弦动画，不是当前 100ms PCM 的真实包络；AGC 或比例不合适时，看起来几乎固定，无法直观看出有没有声音。

### Hub 服务端

1. 录入 WAV 和转码 WAV 写入 Mywork inbox，成功后也不删除，违反“只存 embedding”。
2. `Content-Length` 没有完整校验，短读可能被当作完整样本。
3. 声纹库直接覆盖写入，没有锁、原子替换和私有权限，并发时可能损坏。
4. 每个名额只保存一个 8 秒整体均值模板，静音和环境噪声会稀释说话人特征。
5. 删除逻辑散落在 HTTP handler，没有统一的声纹库事务接口。
6. 一段多人录音只识别一次，然后把同一个姓名写给所有 ASR 段，必然误标。

## 修复方案

### 设备状态机

- 点击空名额时先原子占用声纹任务，再创建 FreeRTOS task；创建失败立即回滚。
- 同一时间只允许一个录入或删除任务。
- 录入中普通点击全部忽略，只允许点击底部明确的“取消”区域。
- 取消只设置 abort 标志，任务统一释放缓冲、恢复状态，UI 不提前假结束。
- 普通录音收尾最长等待 30 秒，期间允许取消。
- 删除由后台任务执行；服务端确认成功后才清本地 NVS。

### 录入质量

- 设备侧拒绝明显静音、过短和严重削波样本，减少无效上传。
- 服务端再次做时长、RMS、有效语音占比和削波率校验，服务端结果为最终准入标准。
- 8 秒录音切成多个 2 秒左右的有效窗口，保存多个模板和中心向量；同一 slot 重录时事务替换旧模板。

### 实时录音波形

- 每次读取 100ms PCM 后，按屏幕横向分桶计算真实短时 RMS/峰值包络，不再绘制与音频无关的固定正弦形状。
- 使用 dBFS/对数映射和快速上升、缓慢回落的平滑方式：安静时波形收缩，说话时按实际音量和节奏起伏。
- 波形只消费已经写入录音缓冲的数据，不额外读取麦克风，不影响录音完整性。
- 屏幕锁忙时允许丢 UI 帧，但绝不阻塞或丢弃录音数据。

### 存储与隐私

- HTTP handler 使用系统临时目录处理录入音频，`finally` 删除源文件和转码文件。
- 声纹目录权限 0700、库文件权限 0600。
- 使用进程内重入锁和“临时文件 + fsync + os.replace”原子更新库。
- 删除统一调用声纹模块 API，按 slot 删除所有模板。

### 分段识别

- WAV 只读取一次，按每条 ASR segment 的 `start_ms/end_ms` 截取 1.5–3 秒上下文。
- 每段分别与 5 个名额的多模板比对。
- 分数达到高阈值直接认定；中间区间只在前后 10 秒高置信片段投票一致时认定；否则归“其他人”。
- 低置信一律归“其他人”，不做访客聚类、不硬猜。

## 验证项

1. 连续快速点击两个名额，只能创建一个录入任务。
2. 录音刚结束时能等待 recorder 完整收尾，不再 3 秒误失败。
3. 录入中普通触摸不取消，底部明确取消可终止。
4. HTTP 部分写入不会被误判成功。
5. 删除请求失败时，本地名额和 NVS 保持不变。
6. 静音、过短、严重削波录音无法入库。
7. 同一 slot 重录会原子替换，库文件始终是合法 JSON。
8. 录入处理结束后不保留原始 WAV。
9. 多个 ASR 段逐段识别，不再整段统一覆盖同一个 speaker。
10. 固件完成 IDF 编译，Hub 完成 Python 编译和单元测试，串口空闲后刷机实测。
11. 实机静音、轻声、正常说话和拍手时，录音页真实波形幅度有明显层级变化。
