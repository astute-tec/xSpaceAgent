## 离线队列策略（已实现）

用户要求："尽可能多存，超出的删最旧保最新"——已实现：


## 已知限制：AUTO 模式下喊"小智"不响应

**原因**：AUTO 模式 = 麦克风持续录音。AFE 的唤醒检测需要独占麦克风，
录音中唤醒词不会被检测到（这是刻意设计，避免录音和问答冲突）。

**要同时支持"边录音边喊小智"需要**：
1. AFE 同时做录音和唤醒检测（技术上可行但需要回声消除处理）
2. 或者改为"先停录音再听唤醒"（会丢一段录音）

**当前替代方案**：在设备屏幕上**双击**触发语音问答（不中断录音）。

## 显示噪点修复（13:30）

**根因**：display_flush 里每 2 行传输间有 `vTaskDelay(1ms)` 延迟，
导致整屏刷新耗时 ~230ms，期间帧缓冲被下一个 `show_level` 调用修改，
造成画面撕裂（部分行是旧内容部分是新内容 → 看起来像噪点）。

**修复**：移除 display_flush 内的延迟，改为连续快速传输。
SPI 传输本身足够快（QIO 40MHz），不需要人为延迟。

## v1.5 上面键行为修正（19:20）

**用户反馈**："上面按钮再按一下就出现麦克风页面，像是卡住了"。

## v1.7 界面确定性改造（14:00）

**用户反馈**：录音时闪烁二维码；下滑显示二维码后一会黑屏；要求行为确定。

**两个根因（都在 connect_task：开机自动连 WiFi）**：
1. 连 WiFi **失败时**它会绘制二维码（"回到配网界面"的旧逻辑）→ 覆盖录音/菜单界面 → 闪二维码
2. 连 **成功后** 5 秒画待机页；失败画二维码后又被录音任务"静音 10 秒熄屏" → 黑屏

**修复：引入 UI 仲裁（单一屏幕主人）**

| 屏幕主人 | 条件 |
|---|---|
| 录音任务 | recorder_is_busy() |
| 设置菜单 | menu_active() |
| 配网页面 | prov_ui_active() |
| 其他（连接流程） | **一律不画屏幕**，只写日志 |

- 连接 WiFi 成功/失败：**完全不碰屏幕**（成功只更新状态，失败只记日志）
- 录音任务绘图前检查 `menu_active() || prov_ui_active()`，任一为真则跳过
- 静音自动熄屏同样加了这两个守卫
- 进菜单时强制 `display_brightness(0xC0)` 保证亮屏
- 断网自动重连：每 5 分钟一次，同样不碰屏幕

**实测**：开机 + WiFi 失败场景 = QR 绘制 0 次、白屏 0 次、看门狗 0 次。

## v2.2 配对码丢失修复（15:10）

**问题**：配网页看不到配对码。

**根因**：配对码只在"开机无 WiFi 凭据"的分支里生成。如果设备已保存 WiFi（直接连 STA 模式），
`s_pair_code` 一直是空串，`draw_pair_code()` 直接返回 → 屏幕没有配对码。

**修复**：把配对码生成放进 `ap_ssid_ensure()`——无论从哪条路径进入配网页都保证有 6 位码。
同时把配对码字号缩小（28×52）并上移到 y=376，适配圆屏底部宽度。
