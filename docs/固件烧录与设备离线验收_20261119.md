# 2026.11.19-rc1 固件与离线验收

设备：Waveshare ESP32-S3-Touch-AMOLED-1.75C（32 MB Flash / 8 MB PSRAM）。

## 状态

这是录音优先架构候选版；代码构建和主机测试完成后才能发布构建结果。设备不在电脑旁，尚未烧录、清理设备存储或完成两小时连续离线实机验收。

## 已有同型号固件的设备：只升级应用

升级前先长按下键 3 秒保存当前录音，接通稳定 USB 电源，关闭占用串口的监视器。保留 NVS、WiFi、声纹、本地待传录音和唤醒模型，不运行 `erase-flash`，不使用整片擦除或全量分区刷写。

在固件所在目录运行（将串口改成实际值，Windows 可为 COM3）：

```sh
python -m esptool --chip esp32s3 --port /dev/cu.usbmodem1101 --baud 460800 write-flash 0x10000 wifi_provision.bin
```

上面命令仅适用于已有相同分区表和唤醒模型的这批设备。新板、其他型号、原厂分区表不得直接套用；需另行核对完整初始化流程。

## 空间审计和安全清理

1. 设备接回后先读取串口 `STATUS`、`STORAGE`、`QUEUELS`，记录清理前空闲量、待传文件数和离线秒数。
2. 联网后发送 `CLEAN`。它只请求补传，服务端落盘并返回匹配的片段 ID、长度和 SHA256 后，设备才删除对应副本。旧 `CLEAR` 也采用相同安全行为，不再盲删录音。
3. 观察队列减少后再次读取 `STORAGE`，记录清理后数据。`.part`、`.bad` 等保留文件需先检查可恢复性，不自动删除。
4. `offline_seconds >= 7200` 且 `two_hours=1` 只是当前空闲空间满足两小时预算，不代表电池或连续录音稳定性已验收。

## 两小时实机验收

- 关闭 WiFi，记录开始时间、队列/空闲空间和电量；长时间测试可先使用 USB 供电，将电池续航单独测试。
- 开始连续录音，期间每隔固定时长说出时间标记；涵盖静音、小声、普通说话和环境噪声；熄屏期间继续录音。
- 连续满 120 分钟后长按下键 3 秒保存。核对音频采样数、时间标记、片段数、Opus worker 栈水位、AFE overflow、重启/卡死日志和实际音质。不能仅看波形判定成功。
- 恢复 WiFi，核对服务端去重回执、重试、归档、逐段声纹和唐僧日报。确认无缺片后再释放设备副本。
- 另测双击上键 / 你好小智 / 长按屏幕三种问答入口、单击上键提交、文字滚动、首段播报和问答后续录。
- 当前 AEC 尚未实测启用，播报期间工作录音仍跳过扬声器回声；该场景存在录音空档，不能声称已经全天无间断采集。

## 容量口径

16 kHz 单声道，20 kbps CBR Opus，每 20 秒一段；每段按 54,000 字节上限并按 8 KiB 分配对齐，预算 57,344 字节。两小时 360 段共 20,643,840 字节（19.69 MiB）。存储分区 25.94 MiB，另预留 1 MiB；未计文件系统开销与设备已有文件时，上界约 152 分钟。最终以设备 `STORAGE` 和两小时实录结果为准。
