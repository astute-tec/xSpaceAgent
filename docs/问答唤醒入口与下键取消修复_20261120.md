# 问答唤醒入口与下键取消修复

日期：2026-11-20

## 最新明确交互

- 仅上键连续双击或本地“你好小智”唤醒词允许进入问答。
- 屏幕长按、双击及其他触摸操作均不可唤醒问答；保留菜单、声纹、表盘等已有触摸用途。
- 问答聆听、提交、等待、播报阶段，下键短按立即取消本次问答，丢弃在途回答，不再播报；随后继续日常录音。
- 日常录音时下键短按仍熄屏/亮屏，长按三秒保存并停止录音；不更改录音文件或声纹资料。

## 实施与验证计划

先核对触摸入口、按键分类和问答任务所有权，再收紧入口、补取消检查；用实际代码的宿主状态测试覆盖聆听、等待 HTTP、播放和快速取消后重新唤醒，构建后核对结果。当前设备正在采集，烧录需在保存收尾后进行。

## 已完成实现与代码验证

- 删除主页长按 260ms 和屏幕双击的问答入口，也关闭串口 ASK 直达入口；仅保留上键双击与 AFE 唤醒词路由。菜单下滑、菜单长按声纹删除等既有用途保留。
- 下键在按下沿取消问答；该次按住不会继续触发三秒停止录音，也不在松手时额外熄屏。普通录音下原有屏幕/长按停止规则保留。
- 取消标记仅由新问答会话清除；等待 HTTPS 锁改为可取消短等待，连接建立限定十秒。连接成功后用受生命周期锁保护的 socket shutdown 打断读取，HTTP 清理由原任务负责，不从按键线程销毁客户端。
- 语音消费者和生产者都检查取消，停止继续播放缓存的旧回答；本地失败/没听清提示同样可取消。取消后清空旧文字，保持问题缓存所有权到采集线程退出，再恢复日常录音。
- 问题采集使用可中断 AFE 读取，停止/取消后每次环形缓冲等待最多 50ms，不再等原四秒超时；不改变普通录音读取逻辑。
