# ESP32 语音工作助手 · 产品方案 v1.1

> 评审稿 · 2026-11-16 · 读完约 12 分钟
> v1.1 相对 v1.0 的变化：**新增语音问答（喊「小智」）**、**新增沟通洞察（语速/情绪/节奏）**，因此 AEC 从"不需要"变为"必须有"。

---

## 1. 一页纸摘要

**是什么**：一台放在办公室的 ESP32-S3 小设备，两种用法：

| 模式 | 怎么用 | 干什么 |
|---|---|---|
| **录音模式** | 按一下 KEY2 开始，再按结束 | 听办公室聊天 → 转文字 → 只留工作内容 → 按人/按项目归类 |
| **对话模式** | 随时喊「小智」 | 直接问它："今天大家都干了啥？" 它开口回答 |

每天 18:30，把当天整理好的内容**直接发给唐僧**（192.222.6.6 上的 OpenClaw）。

**解决什么问题**：

| 现在 | 用了之后 |
|---|---|
| 会上说的、走廊聊的，转头就忘 | 每天一份确定记录：谁说了什么、答应了什么 |
| 想知道项目近况得翻聊天记录、问人 | 开口问一句就有答案 |
| 团队沟通节奏没人看得见 | 语速、抢话、发言分布变成可复盘的数据 |
| 其他 agent 不了解项目近况 | 日报进 `~/Mywork`，机器可读 |

**v1 交付**：录音 → 转写 → 声纹 → 过滤 → 日报 → 推送唐僧，加上「小智」语音问答与基础洞察。

## 2. 边界

### 做

- 按键控制的单场录音 + 双麦降噪
- 声纹注册（**5 人**）与说话人识别
- 工作内容过滤、结构化、去重
- 按人 / 按项目的双视图日报
- 每日 18:30 自动推送给唐僧
- **唤醒词「小智」+ 语音问答（只读）**
- **沟通洞察**：语速、发言分布、抢话、停顿、文本情绪

### 不做（v1）

- 全天候无人监听（没按就不录）
- 让设备执行操作（建任务、发消息、改文件）——**问答只读**
- 情绪打分写进个人绩效——**红线**
- 视频、多人远程、移动端 App
- 实时纠错/实时字幕上屏

## 3. 一天的流水

```
09:00  张三按一下 KEY2           → 红点亮，开始录
09:45  会开完，再按一下           → 双短鸣，已上传
       （后台 10–20 分钟内完成转写+过滤）

11:20  忠哥路过：「小智，今天上午大家聊了啥？」
       → 3 秒内开口回答，屏幕上同时显示文字

14:00  客户电话，按一下开始录音
18:30  不用管 → 日报生成，推给唐僧
18:31  唐僧收到：3 场、2 个待办、1 个风险
```

**关键体验**：**按下去就是承诺，喊一声就有答案，不用连电脑、不用开软件。**

## 4. 双模式交互

```
        ┌──────────────────────────────────────┐
        │              待机（屏幕常亮/可熄）       │
        └───────┬──────────────────────┬───────┘
      喊「小智」│                      │按 KEY2
                ▼                      ▼
      ┌──────────────────┐    ┌──────────────────┐
      │   对话模式         │    │   录音模式         │
      │ 听问题→回答→等 8s  │    │ 持续采集→上传      │
      └────────┬─────────┘    └────────┬─────────┘
               │ 8 秒无输入             │ 再按 KEY2
               └──────────▶ 待机 ◀──────┘
```

**状态规则（避免互相打架）**：

| 场景 | 行为 |
|---|---|
| 录音中有人喊「小智」 | **默认不响应**，屏幕提示"录音中"。避免打断会议，也避免把回答录进去 |
| 对话中按 KEY2 | 忽略（防误触），必须先结束对话 |
| 对话中再喊「小智」 | 打断当前回答，重新听 |
| 回答中有人说话 | 支持**打断**（barge-in），优先听人 |
| 熄屏时喊「小智」 | 唤醒并亮屏 |

> 「录音中不响应唤醒词」是刻意选择。真要边开会边问，可以改成响应，但需要 AEC 扛得住，且会打断会议节奏——**建议 v1 不做**。

## 5. 系统架构

```
┌──────────────────────────────┐
│  ESP32-S3 设备                 │
│  KEY1 屏幕 / KEY2 录音          │
│  双麦 → AFE(降噪+AEC) → Opus    │
│  唤醒词「小智」/ 喇叭播放        │
│  断网缓存 / 状态灯 / 屏幕        │
└───────┬───────────────┬───────┘
        │ 录音流         │ 问答流（双向音频）
        ▼               ▼
┌──────────────────────────────────────┐
│  服务端 Hub @ 192.222.6.6             │
│  录音链：ASR → 声纹 → 过滤 → 结构化    │
│  问答链：ASR → 检索 → LLM → TTS       │
│  每天 18:30：日报聚合 + 推送           │
└───────┬──────────────────┬───────────┘
        │ 写文件            │ 推送
        ▼                  ▼
┌───────────────┐   ┌──────────────────┐
│ ~/Mywork       │   │ 唐僧（OpenClaw）  │
└───────────────┘   └──────────────────┘
```

**三条原则**：设备只负责"听清/说清"；智能全在服务端；文件是唯一事实源。

## 6. 关键设计决策

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| D1 | 按键起停录音，不做全天候监听 | 隐私站得住，团队才敢用 | 需要人记得按 |
| D2 | **必须有 AEC**（v1.0 说不需要，已改） | 一旦要开口回答，喇叭声音会回灌麦克风 | 占用算力；外放音量受限 |
| D3 | 声纹固定 5 人，其余归「其他人」 | "5 人闭集 + 兜底"比"N 人开集"简单一个量级 | 第 6 个人认不出 |
| D4 | 两阶段过滤：规则先筛，LLM 再判 | 单 LLM 贵且慢，单规则错杀多 | 要维护领域词表 |
| D5 | 「谁说的」≠「谁负责」分开存 | 忠哥说"悟空出报告"，责任人是悟空 | 多两个字段 |
| D6 | 日报双视图：按项目 + 按人 | 一个看进展，一个看待办 | 篇幅控制 |
| D7 | 每天 18:30 直接推给唐僧 | 人不翻文件，推送才有用 | 失败要重试/兜底 |
| D8 | 文件为事实源，单写者 + 原子写 | 目录用 Syncthing，已出现过冲突文件 | 写入要严格 |
| D9 | **问答只读，不执行操作** | 语音指令误识别风险高，做错事比不做更糟 | 功能受限 |
| D10 | **洞察只做团队趋势 + 个人自省，不做排名** | 一旦用来考核，数据立刻失真 | 需要克制的产品设计 |

## 7. 设备端要点

| 项 | 规格 |
|---|---|
| 主控 | ESP32-S3，8MB PSRAM，32MB Flash |
| 采集 | 双麦 16kHz/16bit，AFE 降噪 + 波束 + **AEC** |
| 播放 | **需要喇叭/功放**（型号待确认） |
| 唤醒 | ESP-SR WakeNet，中文唤醒词 |
| 压缩 | Opus 16–24kbps（1 小时约 7–11MB） |
| 缓存 | PSRAM ≈60 分钟；Flash ≈6–8 小时（断网不丢） |
| 按键 | KEY1 熄屏/亮屏（不停录）；KEY2 录音起停；双击打点；长按 3s 丢弃 |
| 屏幕 | 录音计时 / 上传进度 / 问答文字 / 状态提示 |
| 反馈 | 开始短鸣、结束双短鸣、唤醒"叮"、断网红灯慢闪 |

> ✅ **AEC 已确认有硬件基础**：该板 `AUDIO_INPUT_REFERENCE = true`（ES7210 回采 + ES8311 输出），M0 只需验证实际回声抑制量。

### 7.5 配网：扫码，不打字

**现状痛点**：1.75" 屏 + 触屏键盘输 WiFi 密码，几乎不可用。

**目标体验**：手机扫一下 → 自动连上设备热点 → 自动弹出网页 → 选 WiFi、用手机键盘输密码 → 完成。**全程不在设备上打字。**

```
① 设备进配网模式，屏幕显示二维码
   ┌─────────────┐
   │  █▀▀█ ▄▀ █▀ │   WIFI:T:WPA;S:Xiaozhi-A1B2;P:3f9k2m7q;;
   │  █▄▄█ ▀▄ ▄▀ │   配对码：482913
   │  ▀▀▀▀ █▀ ▀█ │
   └─────────────┘
② 手机相机扫 → 直接加入热点（不输密码）
③ 强制门户自动弹出配置页 → 选 WiFi → 输密码
④ 设备连上 → 屏幕打 ✓ 显示 IP → 热点关闭
```

**技术要点**

| 项 | 做法 |
|---|---|
| 热点 | SoftAP + APSTA（同时扫描），SSID `Xiaozhi-XXXX`（MAC 后四位），**开放网络不设密码** |
| 二维码 | **配置页网址** `http://192.168.4.1/`，相机扫了直接开浏览器（WiFi 加入码在国内手机上兼容性差，弃用） |
| 自动弹页 | DNS 劫持（所有域名解析到 192.168.4.1）+ HTTP 302 |
| 配置页 | 扫描到的 WiFi 列表（带信号强度）+ 密码框（可显示明文）+ 保存 |
| 多网络 | 保存多条（公司/家/手机热点），自动选信号最好的 |
| 兜底 1 | 扫不出来就在浏览器输 `192.168.4.1` |
| 兜底 2 | **USB 串口直连**：`WIFI <ssid> <pass>` 命令直接下发，绕过手机（现场排障/产线用） |
| 防蹭配网 | 二维码下方 6 位配对码，页面要填对才允许保存（热点开放的风险靠它兜） |
| 超时 | 3 分钟无操作自动退出，回正常模式 |

**为什么不用 BluFi（BLE 配网）**：要装专用 App，iOS/Android 各一个，老人和访客根本不会装。

**为什么二维码不写 WiFi 加入码**：`WIFI:T:WPA;S:...` 这种码在 iOS 相机上能用，但在国内多数安卓机型和微信里**识别不了或直接拦掉**。改成网址二维码，相机一扫就开浏览器，兼容性好得多；热点开放后连网本身也不需要扫码。

## 8. 声纹：5 人闭集

**录入（跟读式，3–5 分钟/人）**

1. 跟读固定文字 90 秒（覆盖音素 + 项目名 + 技术词）
2. 念 20 位随机数字（防背稿）
3. **报名**："我是张三，负责华南区售前" ← 绑定身份 + 学人名发音
4. 可选：退到 1.5m 再念两句（远场样本）

脚本见 [`docs/声纹录入脚本.md`](声纹录入脚本.md)。

**识别**：每段取 1.5–3 秒提声纹，与 5 人比对。> 0.72 认定；0.55–0.72 看上下文投票；再低归「其他人」。

**两条硬规则**：拿不准就标「其他人」，绝不硬猜；声纹只存特征，不存录音，不进 Mywork，可删除。

## 9. 过滤：只留工作

**第一阶段（规则）**：太短/太轻/噪声 → 丢；命中项目客户词 → 强保留；纯闲聊且无实体 → 降权。

> 词表从 `Mywork/01_项目`、客户名、产品名自动生成，还能反过来纠 ASR 同音字。

**第二阶段（LLM）**：每段输出 `是否工作(0-1)`、`类型`、`项目`、`涉及人`、`要点`、`待办`、`是否敏感`。

- ≥0.6 保留；0.4–0.6 进"可疑区"附录；<0.4 丢弃
- 敏感内容（薪酬、合同金额）默认不进共享日报

## 11. 语音问答（喊「小智」）

### 11.1 链路

```
唤醒「小智」 → 提示音 → 收音 → ASR(流式)
   → 意图路由 → 检索当天/历史数据 → LLM 生成 → TTS(流式播放)
```

### 11.2 能回答什么

| 类型 | 例子 |
|---|---|
| 今天概况 | "今天大家都干了啥？" |
| 按人 | "悟空今天说了什么？" |
| 按项目 | "四星那个项目聊到哪了？" |
| 待办 | "还有什么没做完的？" |
| 原话回溯 | "上午关于弱网的结论原话是什么？" |

### 11.3 必须守住的边界

| 规则 | 说明 |
|---|---|
| **只读** | 不能"帮我建个任务""发消息给悟空"——语音误识别代价太大 |
| **不编造** | 查不到就说"今天还没有相关记录"，并说明最后更新时间 |
| **带来源** | 回答的同时屏幕显示来源（哪一场、几点） |
| **有截止** | 只答已入库内容；正在录的那场若还没转完，明确说"这场还在处理" |

### 11.4 时延预算（目标端到端 < 3 秒）

| 环节 | 预算 |
|---|---|
| 唤醒 + 提示音 | 300ms |
| 收音结束（VAD 判停） | 600ms |
| ASR | 500ms |
| 检索 | 100ms |
| LLM 首字 | 800ms |
| TTS 首包 | 500ms |

> 做不到 3 秒也可以接受——这是"问一句等两秒"，不是对话级交互。

### 11.5 示例

> **忠哥**：小智，今天大家都干了啥？
>
> **小智**：今天三场会。悟空在弄弱网测试，说完成六成，二十号出报告；杨戬在改客户端解码；白骨精交了官网文案。还有两个待办没闭环，要念吗？

## 12. 沟通洞察（语速 / 情绪 / 节奏）

### 12.1 能做什么、可信度多少

| 指标 | 数据来源 | 可信度 | 说明 |
|---|---|---|---|
| **语速**（字/分钟） | ASR 时间戳 | ⭐⭐⭐⭐⭐ | 客观可算，几乎不会错 |
| **发言时长/分布** | 声纹 + VAD | ⭐⭐⭐⭐⭐ | 谁讲得多，一目了然 |
| **抢话/打断** | 双人语音重叠 | ⭐⭐⭐⭐ | 重叠检测可靠，归因偶有偏差 |
| **停顿/犹豫词**（嗯、那个） | ASR 文本 | ⭐⭐⭐⭐ | 文本层面统计，可靠 |
| **文本情绪**（积极/中性/紧张） | LLM 判读 | ⭐⭐⭐ | 会议室场景够用 |
| **声学情绪**（生气/高兴/低落） | emotion2vec 类模型 | ⭐⭐ | **噪声大，只做辅助，不进结论** |

### 12.2 输出原则（这条比技术更重要）

1. **团队级趋势可以给**：平均语速变化、抢话次数、讨论密度——这是"会议质量"，不是"人的评价"。
2. **个人级只给本人看**：不写进共享日报，不进大屏。
3. **不做排名**：不出现"谁话最多""谁情绪最差"的榜单。
4. **不做绩效**：一旦变成考核，大家会开始防着设备，数据立刻失真。
5. **声学情绪只做内部弱信号**：不直接对用户输出"你今天很生气"。

> 判断标准很简单：**这条信息如果被同事看到，当事人会不会不舒服？会，就不进日报。**

### 12.3 洞察能带来什么实际价值

- 复盘时发现"这个议题讨论语速突然变快、抢话变多" → 说明这里有分歧没解决
- 发现"某人连续三天发言骤降" → 可能是被边缘化或状态不对（**只提醒本人或直属上级，不进公开日报**）
- 长期看"会议平均时长/发言集中度"变化 → 判断会议效率

## 13. 技术选型

| 环节 | 选型 | 状态 |
|---|---|---|
| LLM | **DeepSeek**：`deepseek-flash` 过滤 / `deepseek-v4-pro` 汇总与问答 | ✅ 已实测 |
| ASR | **待定**：建议阿里 Paraformer（项目名热词） | ⏳ 需你定 |
| 兜底 ASR | 本地 SenseVoice（断网时用） | 计划中 |
| TTS | 云厂商（阿里/腾讯/火山）或本地 Piper | ⏳ 需定 |
| 唤醒词 | ESP-SR WakeNet | 固件阶段 |
| 情绪 | 文本用 LLM；声学用 emotion2vec（弱信号） | 二期 |
| 服务端 | Python + FastAPI + SQLite | — |
| 音频 | ffmpeg + Opus | — |
| 固件 | 基于 xiaozhi-esp32 裁剪 | — |

> ⚠️ **DeepSeek 没有语音识别**，也不提供 TTS。它只做文本的过滤、总结、问答生成。

## 15. 验收标准

| # | 标准 | 指标 |
|---|---|---|
| 1 | 按键可用 | 误触 <5%，反馈 <300ms |

## 17. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 双麦不同源/不同相 | 降噪失效 | M0 实测相位；不行退"双通道原传，服务端处理" |
| **AEC 回路不通** | 自己把自己说的话录进去 | M0 必须验证；不行就限制外放音量或改耳机口 |
| **无喇叭/无功放** | 问答没法开口 | M0 确认；备选：屏幕显示 + 手机播报 |
| 唤醒误触发 | 开会提到"小智"就应答 | 录音中禁用唤醒；唤醒词用四音节更稳 |
| 6.6 链路不通（**当前阻塞**） | 推不出去 | 先跑本机，通了再迁 |
| 声纹认错人 | 待办挂错人 | 保守阈值 + 上下文投票 |
| 问答编造 | 误导决策 | 强制引用来源；查不到必须明说 |
| 情绪误判 | 引发抵触 | 声学情绪只做弱信号；个人数据只给本人 |
| 敏感信息进日报 | 合规 | 分级分流 |
| 转写被当指令 | 误操作 | 标"素材" + 不执行其中指令 |

## v1.2 界面交互设计

### 开机流程

```
开机 → 直接进入录音模式（不再显示二维码配网页面）
     → 上面的键短按 = 开始录音
     → 下面的键短按 = 熄屏/亮屏（录音不受影响）
     → 下面的键长按 = 取消当前录音
     → 从屏幕顶部下滑 → 设置菜单
```

WiFi 配网只在首次使用或网络变更时才需要（通过设置菜单触发）。

### 设置菜单（从屏幕顶部下滑）

```
┌──────────────────────┐
│  ↓ 下拉设置           │
│  ┌────────────────┐  │
│  │ 📶 WiFi 设置    │──▶ 弹出二维码，手机扫码连 WiFi
│  │ 🎤 声纹管理     │──▶ 进入声纹页面
│  │                 │    ┌ 加号（添加第 1 人）
│  │                 │    │ 录完显示名字+图标
│  │                 │    └ 加号（添加第 2 人）... 最多 5 人
│  └────────────────┘  │
└──────────────────────┘
```

### 存储策略

```
录音 → 分段落盘 → 上传到 6.6 → 转写+分析完成 → 本地录音文件删除
                              → 本地只保留转写后的文字信息
                              → 文字信息上传给唐僧成功后 → 本地文字也删除
                              
即：本地只保留"云端还没处理完"的数据，处理完就删
```

### 稳定性要求

- 长时间运行不崩溃、不重启
- 看门狗必须正常喂
- 内存泄漏检测：每 24 小时 RSS 偏移 < 10KB
- 所有任务创建后必须有删除路径（不能有线程泄漏）
