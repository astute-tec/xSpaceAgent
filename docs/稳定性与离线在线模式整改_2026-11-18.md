# 稳定性、录音优先与离线/在线模式整改（2026-11-18）

## 目标和边界

录音是最高优先级。屏幕、网络问答和模型推理不得阻塞或消费录音音频。录音必须先可靠落本地 Flash 队列；联网时异步补传，断网时继续录音。问答是可选的在线功能，不能挤掉或误结束录音。

## 本轮确认的问题

1. 波形在录音任务里每 100ms 计算并整屏刷新一次，显示刷新可能导致波形卡顿并占用音频任务时间。
2. 波形取自 NS/AGC 处理后的 AFE 输出。AGC 会压平真实音量变化，因而显示电平和外界声音不一致。
3. AFE 输入采集线程已有原始麦克风 PCM，可以低成本计算 pre-AGC 声压包络供 UI 使用。
4. 唤醒词在录音中会设置 `s_recording=false`，但 recorder 收尾期间 `s_busy=true`，随后被 `recorder_ask_wake()` 判忙丢弃；唤醒词看似无效。
5. 长按触屏在录音中被 `recorder_ptt_begin()` 拒绝，但触摸状态机仍设置 `ptt=true`，松手后问答缓冲为空；长按问答无法工作。
6. 触屏轻点能停止正在录的会话，违反“只有下面按键长按才能停止”。
7. 下面按键长按停止时日志/UI 称为“取消”，且按下过程调用整屏进度动画；语义不符合保存录音并停止。
8. 离线录音和补传已存在，但问答依赖 WiFi；目前 UI/状态没有充分区分“录音已本地保存”和“在线问答不可用”。

## 实施方案

### 音频与波形

- AFE feed 线程每 10ms 从原始麦克风 PCM 计算 RMS，并写入短历史环形缓冲。
- 录音主循环只采集、计算必要的录音 RMS 并写入 Flash 队列；不绘图、不 flush 显示。
- 独立低优先级 UI 任务最多 5Hz 读取原始电平历史并绘制；熄屏时完全跳过绘制。
- 波形电平用原始麦克风（AGC 之前），滚动时间轴约 1 秒；录音文件仍使用 NS+AGC 增强音频。
- 屏幕只在状态变化或 5Hz 波形帧刷新，减少 SPI 与 CPU 负载。不得为省电降低已验证的 240MHz 音频实时余量。

### 停止录音与熄屏

- 下面按键短按仅切换屏幕；录音状态持续，熄屏时不绘制波形。
- 下面按键长按 3 秒是唯一的物理停止动作：完成尾段写盘并显示“录音已停止”，不丢弃音频。
- 触屏轻点不停止录音；录音中长按屏幕仍可进入问答流程。
- 屏幕熄灭与采集、AFE、Flash 队列完全解耦。

### 唤醒和按住说话

- 唤醒词触发时先请求录音任务有序封存当前尾段；不在收尾窗口内因 `s_busy` 丢事件。
- 当前录音尾段完成后再采集问句，网络问答完成后恢复先前的手动录音状态。
- 触屏 PTT 在录音中先封存当前片段，再切到问答采集；松手发送。若录音收尾时手指已松开，取消空问句并恢复录音。
- 状态画面清楚区分“请说话/正在识别/正在思考/正在回答”，避免采集期间错误显示“回答中”。
- 问答 HTTP 或 WiFi 不可用时快速提示离线，并恢复此前录音；离线录音队列保持不变。

### 离线/在线模式

| 功能 | 在线 | 离线 |
|---|---|---|
| 麦克风采集 | 本地增强并分段存 Flash | 相同流程，不依赖网络 |
| 音频安全 | 先本地完整落盘，再异步补传 | 保留队列，联网后续传 |
| 转写/日报 | Hub ASR、DeepSeek 处理 | 延后到联网补传后处理 |
| 语音问答 | `/v1/ask` 远端回答 | 立即提示当前不可用，不阻塞录音 |
| 屏幕 | 原始电平低频更新 | 一样；断网状态另行提示 |

## 验收

1. 稳态/强弱说话时波形随原始输入电平平滑变化，AGC 不会把波形压成恒定高度。
2. 录音波形刷新 5Hz 上限；熄屏期间无屏幕 flush，连续录音文件时长/完整性不受影响。
3. 熄屏录音至少 10 分钟，Flash 队列持续增加且不自动停止；下面键短按亮屏/熄屏。
4. 轻点屏幕、上面键短按均不能停止录音；只有下面键长按 3 秒可以停止并保留尾段。
5. 录音中喊“你好小智”可封存当前段，完成问答后恢复录音。
6. 录音中长按屏幕，显示“请说话”并采集问句，松手后发出；松手过早则恢复录音、不挂死。
7. 断网时录音不受影响，问答快速提示离线，网络恢复后队列正常补传。
8. Hub 端错误、超时或无声回答不能让设备永久停在问答态。

## 风险与说明

- “原始输入电平”由 ES7210/麦克风通道 PCM 计算，并非经过校准的 SPL 分贝计；目标是准确反映相对声音强弱，不宣称绝对声压值。
- 屏幕关闭省背光和 SPI 刷新；唤醒词仍要求 AFE 连续运行，因此不能对正在监听的设备进入深睡眠。240MHz 暂不降频，以免重现 AFE 欠载和录音丢帧。
- 在线问答暂停录音采集的时段会先封存已录音频；问句本身是问答输入，不作为会议音频上传。问答后立即恢复录音。
