# 录音优先架构落地与两小时离线验收

日期：2026-11-19

## 授权与范围

按用户确认实施上一份架构评估，并新增：离线连续录音至少 2 小时；清理设备多余数据并报告实际可用空间；表盘 12 点位置显示 WiFi 信号与电池/充电状态；完成后提交并推送 GitHub。

## 实施前状态

- 当前普通录音是 16kHz/16bit/单声道 PCM，每 20 秒分段，约 115.2 MB/小时；存储分区约 25.94 MiB，预留 1 MiB，PCM 仅约 14 分钟。
- 当前设备满盘会覆盖最旧待传录音，必须取消静默覆盖；挂载失败自动格式化也必须取消。
- 当前接收端先落盘再确认，但普通录音处理无完整的持久队列恢复；问答额外执行一次 DeepSeek 整理问题。
- 工作区保留了此前同一产品的表盘、唤醒、声纹与持续录音修复，合并检查后按明确文件提交，不整体回滚。
- 唐僧 SSH 可达，服务 active，生产文件哈希与前次部署记录一致。
- 初次检查未发现 `/dev/cu.usbmodem*`，因此还没有读取或清理设备空间。不得用理论容量冒充设备实测。

## 实施与验收顺序

1. 核对可用官方编码组件，采用有明确字节预算的压缩录音格式，保留旧 WAV 补传兼容；至少给 2 小时录音留足封装、文件系统和保留空间。
2. 固件增加真实空间/可录时长统计、安全清理入口、可靠回执核对，满盘不删未确认录音，失败不自动格式化。
3. 服务端持久化处理状态并恢复失败任务；删去问答前置问题整理；普通录音增量归档、合并日报，按优先级处理问答。
4. 完成表盘网络/电量状态栏，后台低频读取硬件，不在音频任务阻塞读 PMIC。
5. 构建和针对性测试，通过后部署后端；设备接回并安全保存后备份/清理/刷应用分区，保留 WiFi、唤醒模型和声纹。
6. 核对压缩音频可解码、长度/质量、实际剩余空间、离线容量、断网补传和问答；连续 2 小时实机验收独立记录，未完成不宣称通过。
7. 检查改动/敏感信息，提交到 `codex/` 分支并推送仓库，回报 commit 和未完成的实机项目。

## 结果记录

### 已实现

- 固件采用 16 kHz 单声道、20 kbps CBR Ogg Opus，20 秒分段；40 KiB PSRAM 独立编码 worker，编码不在采集任务执行。
- 不再按 RMS 丢整段静音；保存失败保留 RAM 缓冲并停止覆盖。满盘不删除未确认录音，挂载失败不自动格式化。
- 兼容旧 WAV；上传带 SHA256/片段 ID/可信采集时间，只有完整匹配回执才删除对应本地文件。
- 新增 `STORAGE` 审计；`CLEAN`/`CLEAR` 只触发安全补传。`STATUS` 同时输出音频、显示和容量健康指标。
- 表盘 12 点区域显示真实 WiFi RSSI、电量/充电；后台每 3 秒读硬件，未知电量显示 `--%`，绘图不阻塞音频读取。
- 后端 SQLite WAL + FULL 持久队列，音频 fsync/原子 rename/目录 fsync 后才确认；启动恢复、冲突拒绝、去重、幂等重试和 5 分钟日报合并。
- 日报只读取有 meta 提交标志的完整会话，跳过损坏 JSON；归档原子替换后同步目录。缺少采集时间的旧固件按固定接收日期重试，避免跨午夜重复归档。
- NVS 恢复的旧时钟只用于估计显示，不冒充可信采集时间；本次开机 SNTP 成功前，录音时间戳标记未知（0），服务端以接收日期作保守归档，不伪造离线开机后的真实日期。
- 问答删除前置 DeepSeek 问题整理，ASR 原问题直接给唐僧；新归档事实即时可读。文字先返回，TTS 单声道边收边播，设备播放缓冲有界为 64 KiB，兼容旧完整双声道 PCM 协议。
- 修正本地唐僧通知依赖 SSH 配置、未指定 workspace 时错误写入当前目录的问题；优先使用显式 workspace 或 OpenClaw 实际代理配置，回退到标准 workspace，不猜测代理子目录。生产配置核对为 `/home/xspace/.openclaw/workspace`，写其 memory 并保留 `voice:auto` 标记。
